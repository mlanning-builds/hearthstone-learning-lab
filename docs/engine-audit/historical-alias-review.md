# Frozen Core and original card identities

`expanded/core_identities.json` records 257 literal Standard Core/original pairs. Shared generation, Dark Gifts, deck copy limits and search, original-deck provenance, distinct resurrection, repeated-minion history and Aura grouping use one identity resolver. Historical bodies remain separate from historical pool eligibility; no production historical pool is approved by these changes.

The frozen archive often omits `countAsCopyOfDbfId` on Core reprints. For example, `CORE_CS2_074` has database ID 69522 and Legacy `CS2_074` has database ID 459, with neither carrying an alias tag. Treating these as distinct previously allowed the Legacy version through the historical rejection guard despite Deadly Poison being in Standard.

Each explicit pair supplies both record hashes and database IDs. Review compared its exact original ID, class, type, cost, Attack, Health, Durability, mechanics, schools, races, runes and printed text. Only HTML markup was ignored for the text comparison. Three frozen identifiers use `Core_` casing and are listed literally. No runtime name or prefix matching builds this map. Blizzard's [Core introduction](https://hearthstone.blizzard.com/en-gb/news/23620129/introducing-the-core-set-and-classic-format) describes returning cards and original versions; the exact 257 mappings are this project's frozen-archive review, not a published complete alias table.

The resolver validates the mapped record hashes, follows serialized copy tags and explicit Core pairs transitively, and rejects cycles. Pool and deck grouping build one lookup snapshot for the operation. Ordinary metadata records without an alias need no lookup scan. Generation validates full membership before excluding a proven creator, rejecting duplicate canonical outcomes and historical versions of current Standard cards before sampling. Physical deck selection still permits a different physical copy of its source.

Eleven dedicated tests verify every mapped pair, real Deadly Poison duplicate and historical rejection, alternate creator exclusion, chained aliases, cycle rejection, distinct same-name records, Raptor Herald's explicit yearly alias, ordinary starting-card provenance, real Core/Legacy Sleepy Dragon resurrection, and Dark Gift duplicate rejection. Shared-path focused tests cover the broader callers. Synthetic alternate versions use distinct database IDs.

Forty-eight previously registered historical bodies are original versions of current Standard Core cards: ten vanilla, thirty-six simple and two Deathrattle bodies. They remain available for explicit fixed recipes but are rejected as past outcomes. Tests require both the rejection and continued acceptance of the other reviewed retired-set bodies. Executable bodies do not constitute approved membership contracts.

Eight Core-exclusive entries without original IDs remain distinct. `CORE_EDR_001` (Babbling Bookcase) and `EDR_001` (Hopeful Dryad) have superficially related identifiers but different names, classes and effects; they are explicitly not aliases. `CORE_EDR_004_2026` (Raptor Herald) resolves through its serialized copy tag to `CORE_EDR_004`. Unmapped Caverns of Time relationships remain a membership-review gate. Do not approve the retired-set planning inventory as a complete eligible universe or infer additional aliases solely from printed names. Blizzard's [28.4 alternate-version correction](https://hearthstone.blizzard.com/en-us/news/24046221) establishes why these relationships matter to creator exclusion but does not supply this snapshot's complete alias table.

The read-only `tools/check_core_identities.py` verifier checks pair completeness, exact hashes, database IDs and gameplay fields without registering cards or approving pools. Eight verifier checks cover corrupt or missing entries and formatting-only differences.
