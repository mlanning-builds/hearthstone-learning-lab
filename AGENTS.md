# Project instructions

## User-owned experiments

Do not start self-play training, learning runs, or deck-search experiments. The owner runs training and experiments manually in Jupyter. You may write and repair that code, inspect existing receipts, run non-training rule checks, and validate notebook syntax without executing training cells.

## Simulator scope

Finish the complete pinned Standard catalog and required generated dependencies. A progress checkpoint is not completion. Keep unsupported outcomes explicit; never narrow an outcome pool to implemented cards or invent a replacement distribution.

The current candidate is staging/rebased-88. Preserve the original engine and old experiments. Read the candidate status, completion queue and fidelity gaps before claiming support. Card counts measure written implementations, not independent client certification.

## Validation

Run candidate checks from the candidate directory so imports select the correct engine. Model checkpoints and receipts are bound to exact source fingerprints. Keep existing local models and reports; do not replace or publish them. Update derived inventory and status only when their required checks pass.

## Publication

Keep credentials, virtual environments, model weights, local run files, notebook outputs and archival backups out of Git commits. The repository is intended as an open-source showcase. Source code uses MIT; third-party game data retains its original rights.
